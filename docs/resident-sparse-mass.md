# 常驻CRB到CSR设备衔接

日期：2026-10-14。
本轮接通设备矩阵与稀疏分解。
完整G03仍未验收。

## 范围与接口

`SparseMassPlan`组合两个原计划。
它拥有常驻CRB与稀疏分解。
构造先核对自由度数量与父链。
同维不同拓扑也不能混接。
两个计划复用同一GPU会话。
新状态独占采集与诊断缓冲。
它不接管任意外部计划状态。

| 阶段 | 当前行为 |
| --- | --- |
| `update_position` | 刷新刚体与质心前置 |
| `update_matrix` | 消费新鲜前置，更新设备CRB与矩阵 |
| `update_gather` | 验证设备源，再按真实CSR逐行复制 |
| `update_factor` | 消费新鲜CSR，复用既有分层分解 |
| `update` | 顺序组合四个阶段 |
| `readback` | 验证守卫，发布独立宿主快照 |

归属检查先于失效写入。
外来计划调用保留合法缓存。
无效输入也保留合法缓存。
合法qpos写入废弃全部下游。
CRB刷新废弃采集与因子。
采集刷新也废弃因子。
陈旧CSR不能直接再次分解。
组合不暴露内部独立分解状态。
已发布快照仍保持可读。
外部独立CSR接口仍沿原契约。
两种新鲜性边界不能混用。

## 真实设备数据路径

源缓冲保留原CRB布局：

```text
4 guards + worlds * (10*nbody + nv*nv) + 4 guards
```

目标保留真实CSR布局：

```text
4 guards + worlds * nC + 4 guards
```

采集读取已检查的行宽与列号。
GPU直接复制对应稠密矩阵槽。
它不计算或重排物理数值。
它也不提升或降低精度。
源与目标都保存f32位型。
元数据继续采用i32。
索引计算使用检查后的宽类型。

宿主不回读后再上传物理输入。
采集始终消费实际设备矩阵。
两个新内核不修改原CRB公式。
它们也不修改原分解算式。
旧稠密大块辅助分歧保持。
本轮不借新组合放行旧辅助。

## 守卫与有限值

`matrix_input`本身只检查就绪。
本轮另增GPU源验证内核。
它扫描整个CRB与矩阵载荷。

它逐世界写入独立诊断状态。
宿主只回读状态与状态守卫。
诊断失败阻止后续采集。

采集完成后只回读目标守卫。
目标错误同样阻止新鲜标记。
这些诊断不反馈物理数值。
公开回读还复用原前置检查。
它检查G01所需设备缓冲。
源错误不能静默消失。
本轮没有CPU物理回退。
