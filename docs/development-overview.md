# 开发排程交互总览

本页属于开发工具。
它不属于产品交互层。
它不增加引擎窗口或查看器。

## 数据来源

总览复用原排程（Normify）。
服务启动独立只读进程。
服务仅调用任务查询接口。
它不维护第二套状态。
它不改写任何原始依赖。
它不改变模块标识。

首页关联以下内容：

- 三层迁移与可选评审。
- P0至P11完整产品路线。
- 三层接入原路线的前置。
- 进行、就绪和阻塞队列。
- 完成登记与历史交付。
- 验收、回执及提交记录。

点击任务查看前置和后继。
详情列出依赖链完成记录。
所有历史任务保留查询入口。
分组不自动创建依赖。
同排任务不代表可以并行。
阶段计数不表示完成率。
门禁状态直接来自原任务。
完成登记不等于产品验收。
回执读取不等于证据复验。
提交前回执保留原状态。
最终交付须核对关闭记录。

## 启动

开发机需要Node.js 24。
产品构建不依赖此工具。
本工具没有新增第三方包。
服务复用已安装的排程引擎。
原引擎须支持只读启动。

在仓库根目录运行：

```powershell
node scripts/development-overview/server.mjs --normify-server <已安装的stdio.mjs>
```

参数指向已安装的服务入口。
沿用当前连接配置中的入口。
不提交个人机器绝对路径。
服务读取仓库目录配置。
配置键为`normify.directory`。
它取父目录作为服务根目录。
也可显式传`--normify-root`。
可用`--port`固定本机端口。
默认端口由操作系统分配。

打开输出的本机地址。
默认页面显示关联总览。
页面每分钟刷新一次。
也可点击“刷新原排程”。
刷新不修改任务状态。
服务故障时页面明确报错。
旧快照不冒充实时数据。
停止进程会让地址失效。
重启后使用新输出的地址。

服务仅监听回环地址。
地址包含随机访问路径。
数据接口拒绝跨源请求。
首页允许跨站导航。
服务不公开仓库文件目录。
回执路径必须留在仓库内。
不要把本机地址发布到公网。

## 开发结合

任务仍走原开发流程。
预检、实现和验证分别记录。
提交仍使用逐文件回执。
提交后登记完整提交号。
关闭后刷新总览检查记录。
总览不会自动关闭门禁。
它不把历史通过转授新源码。

维护任务结构仍用原工具。
新任务自动进入全量任务。
新阶段标签保留原始内容。
首页三层卡片采用明确任务表。
迁移主线变更时须同步该表。
映射位于`model.mjs`。
跨链连线直接读取真实前置。
未映射任务仍进入全量查询。

详见[三层排程](three-layer-schedule.md)。
详见[交付流程](normify-delivery-workflow.md)。
