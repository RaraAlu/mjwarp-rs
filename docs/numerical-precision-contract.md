## 数值参考优先级

第一参考标准为原生MuJoCo。
第二参考标准为冻结MJWarp。
先按原生容差判断数值结果。
原生通过即通过该项数值门禁。
此时不要求再通过MJWarp对照。
仅原生超差后启用第二参考。
第二参考通过也通过数值门禁。
两路均超差则判失败。
第二参考缺失则保留待验收。
可选上游诊断不追加否决权。

| 原生MuJoCo | 冻结MJWarp | NP03结论 |
| --- | --- | --- |
| 容差内 | 无需参与判定 | 通过；记录原生通过 |
| 超出容差 | 容差内 | 通过；记录第二参考通过 |
| 超出容差 | 超出容差 | 失败 |
| 超出容差 | 缺参考或缺冻结容差 | 待验收 |
| 缺少有效原生参考 | 不自动启用 | 待补参考或明确适用范围 |

本规则不要求双路同时通过。
两类通过具有相同准入效力。
报告另记实际采用的参考。
原生通过不代表上游逐位一致。
第二参考通过不代表原生达标。
功能范围与计算精度保持不变。
NP01、NP02与NP04仍独立检查。
结构错误不进入容差回退。
哈希、拓扑与索引仍须核验。
非有限值直接判失败。

本次先修改规范与伴随记录。

## 冻结基线

```text
upstream: google-deepmind/mujoco_warp
revision: 71da24d956378a87a703b6e1442b13aec0c4ac29
```

产品计算精度必须跟随该提交。
规则覆盖全部产品物理路径。
辅助物理探针也须遵守。
上游采用f32时全链保持f32。
上游显式混合精度时逐项跟随。
不得私自升精度或降精度。
不得用更高精度冒充数值等价。

上游float与空间向量采用f32。
相关惯量向量也采用f32。
质量因子与偏置力采用同类类型。
依据：[冻结类型](https://github.com/google-deepmind/mujoco_warp/blob/71da24d956378a87a703b6e1442b13aec0c4ac29/mujoco_warp/_src/types.py#L2387-L2439)、[Warp类型说明](https://nvidia.github.io/warp/v1.13/user_guide/runtime.html#data-types)。

| 实际内核 | 模板展开类型、内核ABI与设备缓冲宽度 |
| 编译设置 | fast-math、FMA、降精度选项及工具链版本 |
| 公开结果 | 输出类型与转换舍入位置 |

不得用内部f64规避原生误差。
不得私自采用f16或TF32。

规则不要求跨设备逐位相等。
规则要求类型与精度策略一致。
数值容限仍需逐字段冻结。
不同编译器仍需各自验收。

纯参考与诊断可以采用f64。
它们不得反馈产品物理结果。
原生ABI继续按上游映射转换。
时间戳不冒充物理工作区。
通用传输支持f64不构成豁免。

## 硬性验收指标

| ID | 度量 | 必须达到 |
| --- | --- | --- |
| NP01 | 类型映射率；实际精度偏离数 | 100%；0项 |
| NP02 | 精度证据覆盖率；证据缺失数 | 100%；0项 |
| NP03 | 两级数值判定覆盖率；失败与待验收数 | 100%；均为0项 |
| NP04 | 批量对照条件与性能记录缺失数 | 0项 |

覆盖率分母采用本次验收范围。
范围必须列明字段与内核。
未实现功能不进入局部通过分母。
完整产品须覆盖全部目标路径。
原有辅助也不能继续豁免。

NP01同时检查各层类型。
上游f32对应内部f64即为失败。
最终窄化为f32不能消除失败。
NP02记录冻结提交与具体符号。
它也记录生成内核与编译选项。
NP03先读取原生MuJoCo参考。
仅原生超差后读取MJWarp参考。
原生通过项无需第二参考证据。
超差项必须补齐第二参考证据。
原生版本与上游提交分别冻结。
参考清单必须冻结模型与状态。
输入须采用相同量化规则。
版本或语义差异须单独登记。
缺少同义字段时不得强行比较。
逐字段分别冻结两路容差。
既有原生容差不自动放宽。
第二参考容差仍须给出依据。
先固定字段块，再执行判定。
不得逐元素择优拼接通过。

两路分别采用以下误差公式：

```text
native_ok = abs(actual - native) <= atol_native + rtol_native * abs(native)
warp_ok   = abs(actual - warp)   <= atol_warp   + rtol_warp   * abs(warp)
```

逐项检查后汇总字段块结论。
原生字段块超差才复核同一块。
不得在失败后放宽容限。
报告原生误差与参考身份。
启用第二参考时另报对应误差。
同时保留失败与待验收数量。
产品测试不启动Python。
离线参考不进入产品运行链。

NP04记录相同模型与输入。
它也记录相同世界数与精度。
双方记录GPU与驱动版本。
双方记录预热、同步与计时边界。
记录稳态批量耗时与显存。
冷启动与上传耗时单独报告。
不得用混合精度冒充公平对照。
本规则不虚构固定加速比。
性能目标另按阶段登记。
