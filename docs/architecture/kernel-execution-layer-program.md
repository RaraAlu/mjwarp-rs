# 内核执行层程序（P0–P5）

- 状态：草案 v0.1（L0 文档；未登记片、未排期、未占窗）。目标：按用户 2026-11-12 战略澄清，把「内核执行层/并行计算单元」做成**设备通用**层，为接入其他并行设备预留扩展。
- 依据：`docs/implementation-plan.md` §并行计算单元能力定义（85 项）；`docs/architecture/device-layer-contract.md`（A0）；`docs/development-process-lite.md`（L0/L1/L2）。
- 总验收目标：**85/85 项四要素齐备**（契约 + CUDA 实现 + 测试/证据 + PU 映射，见 A0 §10）。
- 暂定决策（用户可改）：**D1** = 新内核一律走书写面，容量/缺陷修正豁免；**D2** = 第二后端先做 CPU。

## P0 契约 + 盘点（1–2 片，0 窗，0 GPU）

- 片：P0-a A0 定稿（§2/§3/§9/§10 评审通过）；P0-b 85 项盘点表（capability_id → 契约方法 → 现状 → PU/backlog → done 判据）。
- 验收：盘点表 85 行无空行；每个「部分/缺失」有归属；A0 无未决矛盾。
- 产出：`docs/architecture/device-layer-contract.md` + `docs/development-evidence/plan/kernel-exec-index/`（L1 证据，README + JSON，不建 manifest）。

## P1 设备层 trait + CUDA 适配（3–4 片，0 窗，0 GPU）

- 片：P1-a trait 骨架（6 组接口 + mock backend + 单测）；P1-b CUDA 适配（现有 cudarc/NVRTC/launcher 路径平移，不改行为）；P1-c 退项实现与 `DeviceCaps.fallbacks`（10 项退路）；P1-d 错误三分类落地。
- 验收：mock 单测全绿；CUDA 侧现有单测/定向测试不回归；**冻结集身份不变**（A1 清单 sha 对照，L2 证据若触及）。
- 约束：零行为变化；不改内核源形状；不改判据/容差/参考。

## P2 语言层书写面最小试点（2–3 片，0 窗，可选 1 短窗）

- 片：P2-a shim 类型/数学/原子/同步/发射最小面；P2-b 3 个代表内核（逐元素、原子累加、块内协作）走 shim；P2-c 与现状 CUDA 源对照（值级）。
- 验收：3 内核功能/值级通过；**不修改冻结内核**（源形状不变）；若试点需要新源 → 只对新内核，不重冻历史。
- 风险：shim 一旦要求改现有 .cu → 自动升 L2（源形状/冻结集）。

## P3 库层 17 项（6–8 片，0–1 窗）

- 片：P3-a 扫描（`J.1`）；P3-b 排序（`J.2/J.3`）；P3-c 原子族（`H.2/H.3/H.5/H.6`，跨层但同批）；P3-d BVH（`M.1` 构建/重拟合纳入验收）；P3-e tile 算子最小子集（`I.5/I.6`）；P3-f 重解释（`B.8`）；P3-g 诊断/占用率（`L.3`/`G.9`）。
- 验收：每项单测 + 对照（值级/结构）；算子在 CUDA 后端可用；若需 device 测试 → 复用既有 GPU 窗口（不新开）。
- 依赖：P1（缓冲/发射）、P2（书写面）。

## P4 第二后端（4–6 片，0 窗，0 GPU）

- 片：P4-a CPU 后端骨架（Buffer/Queue/Launch/模 mock 化执行）；P4-b 设备层 44 项在 CPU 上的实现/退路；P4-c 代表内核（同 shim 源）在 CPU 跑通；P4-d 功能对照（与 CUDA 同输入，统计/容差，不宣称位级）。
- 验收：同一契约 + 同一内核源可切换后端；CPU 单测全绿；0 GPU 窗。
- 产出：`docs/development-evidence/plan/cpu-backend/`（L1 证据）。

## P5 跨设备判据政策（1 片 + 用户签名）

- 内容：NVIDIA 零偏离；其他后端容差/统计判据；证据形式；哪些字段必须位级（count/address 类整型 vs 浮点）。
- 验收：判据分级表 + 用户签名；不在此阶段宣称任何跨设备等价。

## 暂定决策与可改点

| 编号 | 暂定 | 影响 | 用户可改 |
| --- | --- | --- | --- |
| D1 | 新内核一律走书写面；**容量/缺陷修正豁免** | P2/P3 并行节奏；不暂停则迁移面随内核数增长（产品命名入口 95） | 是 |

## 排期约束

- 写操作串行（仓库单写者锁）；P1/P2 不占 GPU 窗；P3 如需 device 测试复用既有窗口，不新开。
- B0 定义类五片（PU-01/02/12/17/13+14）继续压后，等本 program 定稿后按 P1 排。
- 每片按 L1（1 卡 ≤2 提交）执行；触碰判据/冻结/窗自动升 L2。

## 风险

1. P2 若 shim 要求改写现有内核 → 冻结集重冻（L2），需先算清 10 exe 身份变化面。
2. P3 的 `J.2/J.3`（排序）与 `H.2/H.3/H.5/H.6`（原子）是硬缺口，且排序依赖扫描，须按 P3-a → P3-b 顺序。
3. P4 用 CPU 验证抽象，但 CPU SIMD 与 GPU 的数值差异需在 P5 判据里预先定级，否则会返工。
4. 「85/85」是阶段目标，不等于对外验收；对外仍按 L2 判据与签名。
