# 内核执行层程序（P0–P5）

- 状态：草案 v0.2（2026-11-12 修订：P3 片名按实际切片、新增 P3-w 收口窗口片与 P4'；A0 已同步 P1-b S1 `e8ef68e89` 签名；L0 文档；未登记片、未排期、未占窗）。目标：按用户 2026-11-12 战略澄清，把「内核执行层/并行计算单元」做成**设备通用**层，为接入其他并行设备预留扩展。
- 依据：`docs/implementation-plan.md` §并行计算单元能力定义（85 项）；`docs/architecture/device-layer-contract.md`（A0）；`docs/development-process-lite.md`（L0/L1/L2）。
- 总验收目标：**85/85 项四要素齐备**（契约 + CUDA 实现 + 测试/证据 + PU 映射，见 A0 §10）。
- 暂定决策（用户可改）：**D1** = 新内核一律走书写面，容量/缺陷修正豁免；**D2** = 第二后端先做 CPU。

## P0 契约 + 盘点（1–2 片，0 窗，0 GPU）

- 片：P0-a A0 定稿（§2/§3/§9/§10 评审通过）；P0-b 85 项盘点表（capability_id → 契约方法 → 现状 → PU/backlog → done 判据）。
- 验收：盘点表 85 行无空行；每个「部分/缺失」有归属；A0 无未决矛盾。
- 产出：`docs/architecture/device-layer-contract.md` + `docs/development-evidence/plan/kernel-exec-index/`（L1 证据，README + JSON，不建 manifest）。

## P1 设备层 trait + CUDA 适配（3–4 片，0 窗，0 GPU）

- 片：P1-a trait 骨架（6 组接口 + mock backend + 单测）；P1-b CUDA 适配（现有 cudarc/NVRTC/launcher 路径平移，不改行为）；P1-c 退项实现与 `DeviceCaps.fallbacks`（10 项退路）；P1-d 错误三分类落地。
- 验收：mock 单测全绿；CUDA 侧现有单测/定向测试不回归；**冻结集身份不变**（A1 清单 sha 对照，L2 证据若触及）。
- 约束：零行为变化；不改内核源形状；不改判据/容差/参考。

## P2 语言层书写面最小试点（2–3 片，0 窗，可选 1 短窗）

- 片：P2-a shim 类型/数学/原子/同步/发射最小面；P2-b 3 个代表内核（逐元素、原子累加、块内协作）走 shim；P2-c 与现状 CUDA 源对照（值级）。
- 验收：3 内核功能/值级通过；**不修改冻结内核**（源形状不变）；若试点需要新源 → 只对新内核，不重冻历史。
- 风险：shim 一旦要求改现有 .cu → 自动升 L2（源形状/冻结集）。

## P3 库层 17 项（8 片实现 + 1 窗口片，0–1 窗）

- 片与顺序（**2026-11-12 编号裁定**，取代原「P3-b = J.2/J.3 合并、P3-c = 原子族、P3-d = BVH」等旧编号）：

| 片 | 内容 | 依赖 | 提交 |
| --- | --- | --- | --- |
| P3-a | `J.1` 扫描 `array_scan`（inclusive、i32 补码回绕） | 设备层就绪（P1-b） | ≤2 |
| P3-b | `J.2` `segmented_sort_pairs`（两路线逐位一致、并列键稳定） | P3-a | ≤2 |
| P3-c | `J.3` `radix_sort_pairs`（keys 缓冲 ≥2×count、稳定） | P3-b | ≤2 |
| P3-d | 原子族 `H.2/H.3/H.5/H.6`（复合原子 + 标量原子补齐） | P3-c | ≤2 |
| P3-e | `M.1` BVH 构建/重拟合纳入验收 | P3-d | ≤2 |
| P3-f | tile 算子最小子集 `I.5/I.6`（含排序散布，供 `J.2` tile 路线） | P3-e | ≤2 |
| P3-g | 重解释 `B.8` | P3-f | ≤2 |
| P3-h | 诊断/占用率 `L.3`/`G.9` | P3-g | ≤2 |
| P3-w | **收口窗口（非实现片）**：1 短窗 ≤10 min 跑 `J.1`/`J.2`/`J.3` 三条 `#[ignore]` 值级测试，L2 证据 | P3-a/b/c 全 verified | 窗口卡 `2026-11-12-p3w-closeout-window` |

- 验收：每项算法单测 + 对照（值级/结构）；算子在 CUDA 后端可用；`P3-w` 窗前三点基线 + 窗内 guard，失败即停（不重试、不放宽）。
- 依赖：P1（缓冲/发射）、P2（书写面）；`J.1 → J.2 → J.3` 严格顺序，不建议把 `J.2/J.3` 合并（2× 工作缓冲与稳定性语义独立）。
- 骨架：P3-a/b/c + P3-w 的 ready-to-register 卡在 `target/impl-plan-review/card-skeletons/`（未登记）；GPU 值级测试以 `#[ignore]` 登记、由 P3-w 统一执行。

## P4 第二后端（4 片，0 窗，0 GPU；D2 仍暂定）

- 片：P4-a CPU 后端骨架（`Buffer/Queue/Launch` + `DeviceCaps`）；P4-b 44 项设备层在 CPU 上实现/退路（38 原生 / 5 语义差异 / 1 退路，见 `target/impl-plan-review/p4-cpu-backend-feasibility.md`）；P4-c 代表内核（同一 shim 源）在 CPU 跑通 + CPU 标量参考对照；P4-d 能力矩阵报告 + 同源双端结构对照。
- 依赖：**P4-c 硬等 P2-a/b**（否则「同一内核源」不可验证）；P4 只做单线程块（`I.3` 为顺序桩）。
- **P4'（未排，不计入 P4）**：CPU 真多线程块（`std::thread::scope` + `Barrier` + 块共享区；受限 `unsafe`/确定性另评，需单独计划）。
- 边界：不做跨设备数值对照（`E.2` 三角/幂差异归 P5 容差，用户签名级）；不宣称位级一致。
- 验收：同一契约 + 同一内核源可切换后端；CPU 单测全绿；0 GPU 窗。
- 产出：`docs/development-evidence/plan/cpu-backend/`（L1 证据）；可行性稿在 `target/`（工作材料）。

## 排期约束

- 写操作串行（仓库单写者锁）；P1/P2 不占 GPU 窗；P3 如需 device 测试复用既有窗口，不新开。
- B0 定义类五片（PU-01/02/12/17/13+14）继续压后，等本 program 定稿后按 P1 排。
- 每片按 L1（1 卡 ≤2 提交）执行；触碰判据/冻结/窗自动升 L2。

## 风险

1. P2 若 shim 要求改写现有内核 → 冻结集重冻（L2），需先算清 10 exe 身份变化面。
2. P3 的 `J.2/J.3`（排序）与 `H.2/H.3/H.5/H.6`（原子）是硬缺口，且排序依赖扫描，须按 P3-a → P3-b 顺序。
3. P4 用 CPU 验证抽象：数值差异已在可行性稿分级（`E.2` 三角/幂归 P5 容差；跨设备数值对照不做），剩余风险 = CPU 真多线程块（P4'）与 SIMD 并行缺位，可能使「并行语义」验证不完整。
4. 「85/85」是阶段目标，不等于对外验收；对外仍按 L2 判据与签名。
