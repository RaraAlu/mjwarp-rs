# 七维MathDx原生链接与设备调用

日期：2026-10-14。
本轮落实七维原生链接依赖。
本轮不改Rust产品物理路径。
原柔体面算子与容差保持。
原满额测试继续冻结。

## 链接与算子边界

上轮已生成七维中间产物(LTO)。
本轮直接复用原始字节。
本轮没有重复能力查询。
本轮也没有再次生成求解器。

独立工具调用原生编译接口。
接口名称为`wp_cuda_compile_program`。
它采用22个C ABI参数。
指针与size_t采用64位。
整数采用32位，bool采用1字节。
工具通过受限路径装载DLL。
工具核对原WHEEL RECORD。
驱动库仅从系统目录装载。
工具限制设备架构为SM89。

两份链接输入保持原摘要。

| 输入 | 类型枚举 | 字节数 |
| --- | ---: | ---: |
| 七维POTRF LTO | 3 | 1034872 |
| 原通用fatbin | 4 | 506960 |

编译符号保持以下名称：

```text
potrf_7_7_1_89_32_1_1_5_x_x_0
```

设备调用器采用32线程块。
共享矩阵采用连续49项f32。
共享状态采用单项i32。
各线程参与同一POTRF调用。
调用器在调用前后同步。
随后清空下三角为正零。
它采用公开MathDx分支边界。
它不使用标量回退分支。
它另外导出SDK的info状态。
info导出属于本轮诊断扩展。
它不等于原Warp产品错误策略。

本轮手写独立CUDA调用器。
它不是冻结MJWarp七维模板。
输入采用已知U的精确Gram矩阵。
候选输出不参与定义参考U。
宿主没有执行任何分解算法。
f64仅生成离线参考与诊断。
工具先断言M可精确映射f32。
设备输入、输出与共享量采用f32。
SDK内部类型仍缺完整证据。

## 两轮真实记录

执行同一新增组合目的：

```powershell
scripts/probe-windows-mathdx7-link.ps1 -Attempt 1
scripts/probe-windows-mathdx7-link.ps1 -Attempt 2
```

首轮MSVC准备失败。
脚本误用`/I:包含目录`。
MSVC把冒号纳入目录内容。
它报告找不到`cuda.h`。
本轮修正为`/I包含目录`。
实际头文件与摘要始终存在。
首轮没有进入编译链接接口。
首轮也没有执行设备函数。
原契约、脚本与日志均保留。

第二轮完整通过。
累计用途保持2/3。
成功后本轮没有追加调用。
MSVC采用`/W4 /WX`。
原生接口返回0。
模块装载与八次启动均成功。
