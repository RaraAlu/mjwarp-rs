# mjwarp-rs 项目定位

日期：2026-10-06。
状态：已确认定位与实施边界。

## 核心定位

项目对标MJWarp。
项目交付独立GPU物理引擎。
项目只负责MJWarp相关能力。
LRsLab负责所有应用调用。
LRsLab负责play与交互前端。
Rust负责主API与宿主代码。
内核允许采用Rust或C/C++。
GPU负责批量物理计算。

它不只提供MuJoCo绑定。
它不是Warp的Rust调用包装。
它不是强化学习训练框架。
它不借Python生成产品内核。

包名采用 `mjwarp-rs`。
库导入名采用 `mjwarp_rs`。
库入口导出基础与字段辅助。
探针覆盖P1至P4局部行为。
刚体运动学只提供GPU子集。
质心与惯量也仅提供GPU子集。
质量矩阵仍属于GPU辅助子集。
正定求解也仍属于辅助子集。
几何与site位姿也属辅助子集。
常驻底座复用五个设备子集。
二十三项参数支持独立批量。
GPU支持相机与光源位姿。
GPU支持固定肌腱长度与力臂。
肌腱拓扑与系数仍共享。
空间肌腱仍待实现。
常驻状态支持mocap写入。
GPU初始化静态geom缓存。
更新仍重算全部site。
模型拓扑仍共享一份。
它仍不提供完整等价阶段。
物理引擎API仍待实现。

项目保持独立身份。
名称不表示官方授权或隶属。
发布前需再次检查包名。

## 对标关系

| 层次 | 对标对象 | 主要职责 |
| --- | --- | --- |
| 引擎核心 | MJWarp | GPU物理、数据、渲染 |
| LRsLab应用层 | mjlab | 模型编译、任务、训练与play |
| 原生MuJoCo | LRsLab选用的外部组件 | 模型编译、CPU物理与显示 |
| 学习框架 | LRsLab选用的Burn等库 | 网络、梯度、优化器 |

mjlab区分仿真与管理层。
本项目保持相同职责边界。
我们对标能力，不复制Python。

依据：[mjlab架构](https://mujocolab.github.io/mjlab/main/source/architecture_overview.html)。

## 核心职责

### 模型与状态

核心接收编译后的模型。
核心管理模型与状态缓冲。
核心提供名称与索引映射。
核心支持批量独立世界。
核心支持指定世界的重置。
核心提供状态保存与恢复。

LRsLab负责MJCF加载与编译。
引擎只接收已编译模型。
转换层提取模型与资产数据。
GPU核心使用自己的设备布局。
原生模型不直接充当GPU模型。
原生输入适配可以属于引擎。
它不承担场景编排或XML编译。

依据：[上游模型上传接口](https://github.com/google-deepmind/mujoco_warp/blob/71da24d956378a87a703b6e1442b13aec0c4ac29/mujoco_warp/_src/io.py)。

### 物理计算

核心提供以下能力：

- 运动学与质量矩阵。
- 正向与逆向动力学。
- 执行器与被动力。
- 碰撞、接触与摩擦。
- 关节与其他约束。
- 求解器与积分器。
- 传感器与历史状态。
- 上游支持的柔性体功能。

每项范围跟随冻结版上游。
兼容矩阵定义具体验收项。

### GPU运行与渲染

核心管理GPU执行与同步。
核心管理工作区与资源上限。
核心提供执行计划与图重放。
核心支持批量相机渲染。
核心输出颜色、深度与分割。
核心支持射线与接触查询。

执行图属于物理调度能力。
它不代表策略网络执行图。
项目不承诺完整物理可微分。

### 引擎数据接口

引擎提供状态与控制接口。
引擎提供按世界修改参数的能力。
引擎提供GPU张量视图契约。
引擎提供同步令牌与诊断数据。

随机化策略属于上层框架。
参数修改接口属于引擎。
动作缩放规则属于上层任务。
执行器物理语义属于引擎。

## Rust主接口与无Python边界

项目采用Rust主接口。
宿主逻辑优先采用Rust。
项目允许嫁接C/C++实现。
原生模型与GPU内核均可接入。
项目不要求原生组件改写为Rust。

构建不调用Python脚本。
测试不启动Python进程。
运行不加载Python解释器。
间接依赖也需满足此约束。
Rust包装不能掩盖Python依赖。

原生库允许进入引擎依赖。
CUDA C++内核也允许接入。
原生编译器工具链不构成禁项。
P0冻结版本、许可与部署要求。

| 依赖类别 | 处理规则 |
| --- | --- |
| 主API与宿主业务 | Rust优先，保持Rust调用入口 |
| Python解释器、脚本与桥接 | 构建、产品测试与运行禁止 |
| MuJoCo原生模型输入 | 允许，可提供只读转换适配 |
| MuJoCo原生参考计算 | 允许，用于模型常量或数值测试 |
| 原生GPU渲染组件 | 允许，按批量输出契约验收 |
| 编译器、CPU play与查看器调用 | LRsLab负责，不纳入本crate |
| 手写或移植C/C++ GPU内核 | 允许，保持安全Rust封装 |
| CUDA C++生成路线 | 允许，与LLVM路线共同验证 |
| LLVM、CUDA与系统工具链 | 登记构建及运行依赖 |
| 外部C参考引擎 | 允许，通过Rust测试调用 |

项目不宣称所有依赖都用Rust。
项目也不默认只需驱动即可部署。
P1必须给出真实依赖清单。

### 推荐复用路线

- 引擎接收原生编译模型。
- 引擎转换模型并上传GPU。
- GPU内核选择无Python路线。
- 缺失接口可补充原生FFI。

优先组合组件，不复制整个仓库。
绑定不能导出MJWarp内核。
GPU物理仍需移植或重新实现。
项目不直接调用上游Python包。

## MuJoCo兼容边界

项目兼容模型与物理语义。
兼容范围以MJWarp基线为界。
项目不复刻完整MuJoCo生态。
项目不保证C ABI兼容。
项目不保证Python接口兼容。
MJB二进制兼容需单独决议。

### GPU等价与发行差异

完整等价首先约束GPU引擎。
它包含默认值与有效调用范围。
它包含副作用、警告与失败边界。
Rust门面不能缩减这些语义。

上游还提供CPU开发调试路径。
上游发行包也提供查看工具。
现有项目不交付这些完整路径。
CPU调试不等于CPU play。
因此不宣称发行包完全相同。
最新完整边界要求仍待确认。
本轮继续遵守既有产品边界。
差异与决议见[复审报告](initial-release-review.md)。

原版物理引擎使用C。
原版模型编译器使用C++。
C/C++实现不构成语言禁项。
LRsLab负责原生编译与CPU调用。
引擎只保留必要的模型适配。

依据：[MuJoCo实现结构](https://mujoco.readthedocs.io/en/stable/programming/index.html)。

模型编译不能只解析XML。
原生编译器处理默认值与继承。
它处理资产与惯量计算。
LRsLab组织这些编译调用。
转换层核对拓扑与索引布局。
P0匹配绑定与原生库版本。
版本不符时不能静默截断字段。

依据：[MJCF模型机制](https://mujoco.readthedocs.io/en/stable/modeling.html)。

## 引擎与应用的验收边界

CPU play要求继续保留。
LRsLab负责实现与验收。
本crate不交付CPU play后端。
本crate不交付任何显示前端。
本crate只提供物理状态接口。
策略、回放与调用方案另存应用。

GPU批量渲染仍归引擎。
它生成图像，不创建交互窗口。
LRsLab决定如何展示图像。
前端完成度不计引擎完成率。

## 正式发布定义

首版同时支持两种系统。
首版GPU只要求NVIDIA。
核心完整覆盖冻结版GPU能力。
核心保留等价低层阶段入口。
核心不能只提供严格门面。
核心完成通用数据接口验收。
引擎不等待LRsLab应用发布。
CPU与前端不构成引擎发布门槛。

原型阶段可以只跑小场景。
小场景不能代表正式首版。
倒立摆只是早期探针。
项目不能围绕倒立摆写死模型。

功能、数值与性能分别验收。
项目不承诺长轨迹逐位相同。
项目不预设所有场景都更快。
