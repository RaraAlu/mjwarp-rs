产物缓存与模块缓存已经落地。

物理调用仍走L1原路径。

## 产物缓存

位置：`src/runtime/launcher/artifact.rs`。

产物键含以下七项：

| 字段 | 内容 |
| --- | --- |
| `schema` | 键版本 |
| `program` | 程序名 |
| `source_sha256` | 源码摘要 |
| `headers` | 每个头文件的名称与内容摘要 |
| `recipe` | 配方指纹，含用途与精度门 |
| `arch` | 目标虚拟架构 |
| `nvrtc` | 实际加载的NVRTC主次版本 |

键不含入口名与上下文。
同一源码的多个入口共用一份产物。
治理复核的279组记录支持这一点。
其中119份源码各只对应一份PTX。

查询顺序为内存、磁盘、编译。
同键并发只编译一次。
编译失败不进入缓存。
`cached`只查不编，供捕获期间使用。
`invalidate`与`clear`只清内存。

### 配方隔离

查询前先按用途准入配方。
探针与诊断配方不能换取物理产物。
用途写入配方指纹，所以各自换键。
物理配方的产物必过f32检查。
该检查复用L1的`check_physics_ptx`。
诊断配方不做该检查。

### 磁盘层

磁盘层可选，按键摘要命名文件。
载荷格式为`mjwarp-launcher-artifact-v1`。
它不复用L3探针格式。
写入沿用临时文件加同目录重命名。

| 情形 | 处理 |
| --- | --- |
| 文件损坏或JSON错误 | 报告错误，不静默重编 |
| 未知字段或格式不符 | 报告错误 |
| 载荷摘要不符 | 报告错误 |
| 键与请求不符 | 报告`key-mismatch` |
| PTX摘要不符 | 报告`ptx-digest` |
| PTX含f64运算 | 物理配方报告精度错误 |
| 显式刷新失败 | 保留旧产物 |

磁盘产物载入后重做全部核验。

### 头文件

头文件内容已参与产物键。
内存头文件编译需要W15。
本阶段遇到头文件即明确拒绝。

## 模块缓存

位置：`src/runtime/launcher/module.rs`。

每份缓存绑定一个`CudaContext`实例。
其他实例一律报告`ModuleContext`。
同一主上下文的两个实例也分开。
这样只多加载模块，不会误用函数。

同一产物只加载一次模块。
各入口在该模块中取函数。
函数句柄持有模块引用。
失效后旧句柄仍可使用。
`cached_function`只查不加载。

## 冷启动与稳态

13份源码含24个入口。
“逐入口”模拟L1现行行为。
它每个入口各编一次、各载一次。
单次样本，桌面程序未关闭。
数字只作记录，不作性能验收。

驱动JIT缓存关闭时：

| 阶段 | debug | release |
| --- | ---: | ---: |
| 逐入口编译与加载 | 1668.4毫秒 | 1614.3毫秒 |
| 缓存冷启动 | 1021.3毫秒 | 1349.1毫秒 |
| 磁盘命中重启 | 359.9毫秒 | 313.9毫秒 |
| 稳态一轮24次查询 | 0.645毫秒 | 0.026毫秒 |

驱动JIT缓存开启时：

| 阶段 | debug | release |
| --- | ---: | ---: |
| 逐入口编译与加载 | 1193.0毫秒 | 1143.3毫秒 |
| 缓存冷启动 | 1212.5毫秒 | 1126.2毫秒 |
| 磁盘命中重启 | 44.1毫秒 | 8.1毫秒 |
| 稳态一轮24次查询 | 0.636毫秒 | 0.030毫秒 |

开启时逐入口先跑，预热了驱动JIT。
所以该组冷启动对比有偏差。
关闭JIT缓存后各阶段条件相同。
模块加载显存增量为2 MiB。

磁盘命中省去全部NVRTC编译。
剩余耗时主要是驱动JIT。
NVRTC版本在进程内只查一次。
首版每次查询都调用库函数。
该版稳态为每轮30毫秒，已弃用。
