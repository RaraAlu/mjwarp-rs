完整压缩布局仍留在原计划。
该后测拒绝修复仅通过库编译。
新增拒绝断言本轮未执行。
它不依赖外部模型标签。
源计划必须覆盖借用计划寿命。
数据保留独立模型身份。
相同形状或拓扑不能跨计划混用。

每次update重新检查源归属。
每次update要求源M已就绪。
源世界数必须匹配消费者数据。
调用方决定何时执行CRB。
消费者不自动执行位置或CRB。
消费者不缓存M指针或副本。
合法qpos写入使源M失效。

## 设备布局与精度

源缓冲真实布局如下：

```text
guard4 + worlds * (10*nbody + nv*nv) + guard4
```

产品直接读取该源缓冲。
它显式跨过每世界CRB前缀。
它不复制M到连续矩阵缓冲。
它不下载M后重新上传。
诊断回读不反馈产品。
数据仅拥有以下五个缓冲：

```text
i32 metadata
f32 vector, current, staged, status
```

skip需要保留已有结果。
产品把结果载荷复制到暂存缓冲。
该复制采用设备到设备路径。
该复制不是矩阵复制。
全暂存结果有限后才交换发布。
拒绝或溢出不部分发布新结果。

| 项目 | 映射 |
| --- | --- |
| CRB/M、向量与结果 | f32 |
| acc与乘加 | f32，从正零开始 |
| Sparse顺序 | 冻结io.py镜像追加顺序 |
| Sparse地址 | 源M下三角单元，保持镜像语义 |
| Dense顺序 | 静态nv逐列累加 |
| 拓扑与行、列、地址 | i32 |
| skip | bool转私有i32 |
| 来源跨度计算 | 已检查容量，内部u64索引 |
| 编译 | 原NVRTC12.8、compute70 |
| 融合 | 原fmad开启、fast_math关闭 |
| 参考 | f64条件点积，仅作诊断 |

算子跟随冻结support.py与io.py。
上游提交保持71da24d基线。
实际PTX显示融合乘加。
三种Sparse模块各含五条FMA。
Dense模块分别含3/33/65条FMA。
这些模块不含f64或原子指令。
本轮不插入新舍入屏障。
原物理核、同步ABI与门禁不变。
resident源只新增只读拓扑方法。
旧函数与测试正文逐字不变。

校验器采用静态NV与COUNT。
坏元数据不决定读取跨度。
它先检查行边界与列范围。
它再核对下三角地址。
未跳过世界要求CRB/M/向量有限。
跳过世界不读取坏数据载荷。
全局输入保护槽仍必须完整。
当前缓存结果也须有限。
