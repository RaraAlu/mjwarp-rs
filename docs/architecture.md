## 系统分层

```text
LRsLab应用边界
  模型编译、训练、play、前端、学习库适配
          │
          │ 已编译模型、物理输入、渲染请求
          ↓
mjwarp-rs引擎边界
  模型转换与上传
  批量状态、物理计算、GPU批量渲染
  设备缓冲、完成事件、执行图、诊断
          │
          │ 物理状态、图像缓冲、完成令牌
          ↓
LRsLab应用边界
```

引擎只接收控制与物理输入。
LRsLab解释策略与任务。
LRsLab组织模型编译。
转换层建立GPU数据布局。
引擎不创建play程序或窗口。

## 模块划分

先采用清晰的内部模块。
跨后端复用后再拆分crate。
不要提前发布大量空壳包。

| 模块 | 职责 | 依赖方向 |
| --- | --- | --- |
| `model` | 输入规范、模型与状态布局 | 依赖运行时、数学与诊断 |
| `io` | 原生转换、上传与状态交换 | 依赖模型、物理与运行时等 |
| `math` | 空间代数与纯数学函数 | 只依赖公共诊断 |
| `runtime` | 设备、缓冲、同步与图 | 只依赖诊断与外部工具链 |
| `physics` | 物理阶段、历史与常量刷新 | 依赖模型、运行时、数学与诊断 |
| `render` | 渲染BVH、相机与图像输出 | 依赖模型、运行时、数学与诊断 |
| `diagnostics` | 错误类别与输出有效性 | 不依赖其他内部模块 |

物理Data归模型数据模块。
运行时不解释物理字段。
历史与常量刷新归物理模块。
公开BVH refit归渲染模块。
碰撞加速结构仍归碰撞模块。
IO可组织物理重置流程。
物理模块不能反向依赖IO。
完整依赖关系查首版契约。

不增加CPU play配套模块。
不增加窗口或查看器模块。
不增加Burn适配模块。
LRsLab自行接入这些组件。
公共接口不暴露特定编译器IR。
不同后端可以使用不同调度。

## 已编译模型输入契约

引擎不提供MJCF编译入口。
LRsLab提供已编译模型。
输入可采用原生模型视图。
也可采用等价结构化数据。
两条输入共用GPU转换语义。

```text
调用方提供已编译模型与资产
            ↓
只读模型视图 / 等价结构化输入
            ↓
字段提取、精度转换、GPU能力检查
            ↓
引擎模型布局与GPU常量
            ↓
GPU模型上传
```

输入转换不调用Python。
引擎不解释XML或拼装场景。
状态恢复不得隐式重编译模型。

### 原生输入与转换工作项

- 校验输入语义与原生版本。
- 按需提供只读原生模型适配。
- 提取拓扑、关节与自由度索引。
- 提取网格、地形与纹理资产。
- 提取执行器、肌腱与约束描述。
- 提取传感器、相机与关键帧。
- 映射原生字段与GPU字段。
- 转换精度、索引与矩阵布局。
- 核对常量与动态刷新语义。
- 检查GPU支持能力与容量。

绑定缺项可补充局部原生FFI。
适配层不封装CPU play步进。
模型构造与资产路径归调用方。
P0冻结覆盖GPU范围的输入版本。
绑定版本不构成GPU覆盖证明。

依据：[上游模型上传](https://github.com/google-deepmind/mujoco_warp/blob/71da24d956378a87a703b6e1442b13aec0c4ac29/mujoco_warp/_src/io.py)。

未知物理属性必须报错。
转换层不得静默忽略它们。
错误指出字段、索引与能力项。
输入检查限制尺寸与资产容量。
禁止越界索引与悬空资产引用。

### 模型身份

引擎模型记录以下字段：

| 字段 | 用途 |
| --- | --- |
| `schema_version` | 规范及布局版本 |
| `input_version` | 输入模型的语义版本 |
| `native_version` | 可选原生输入版本 |
| `conversion_version` | 原生到GPU的字段映射版本 |
| `upstream_revision` | MJWarp功能基线 |
| `source_digest` | 调用方提供的可选来源摘要 |
| `model_digest` | 输入字段、资产与转换结果身份 |
| `topology_digest` | 拓扑兼容检查 |
| `capabilities` | 所需后端能力 |
| `dimensions` | 刚体、自由度等尺寸 |

摘要算法在P2固定。
模型摘要必须包含资产内容。
来源摘要不能替代模型内容摘要。
MJB不是本契约的默认交换格式。
原生句柄不进入模型快照。
GPU缓冲不借用原生裸指针。
转换层持有所有者或复制数据。
模型释放不能使在途GPU任务悬空。

## 模型与世界布局

采用模型与状态分离的设计。
模型保存拓扑与物理参数。
状态保存每个世界的动态量。
工作区保存计算中间结果。

共享参数采用广播布局。
字段可使用独立批量长度。
世界参数可采用按世界布局。
周期布局按字段长度取模。
首版契约定义三种批量模式。
参数视图必须声明写入权限。
拓扑修改要求重新编译。

| 数据类别 | 示例 | 布局要求 |
| --- | --- | --- |
| 模型拓扑 | 父子关系、关节类型 | 上传后保持稳定 |
| 公共资产 | 网格、纹理、地形 | 显式所有权与复用 |
| 共享参数 | 质量、阻尼、摩擦 | 允许只读广播 |
| 世界参数 | 随机化后的物理量 | 声明世界维度 |
| 世界状态 | 位姿、速度、执行器状态 | 世界间隔离 |
| 历史数据 | 控制、传感、时钟 | 局部重置同步处理 |
| 接触与约束 | 接触点、雅可比、力 | 区分共享池与世界容量 |
| 工作区 | 分解、归约、BVH临时量 | 预分配与边界检查 |

异构模型按上游能力映射。
不同拓扑不能默认合批。
不足的批量能力不能静默降级。

接触池跨世界共享。
单世界可超过接触分配估算。
约束数组按世界独立分配。
容量契约不能混用这两种语义。

## GPU运行时契约

运行时先提供NVIDIA后端。
接口预留其他设备类型。
首版不承诺其他厂商可用。
不要让CUDA句柄污染模型规范。

### 必须实现的能力

- 设备枚举与能力检查。
- 缓冲分配、回收与池化。
- 上传、下载与设备内复制。
- 流、事件与完成状态。
- 内核编译与缓存管理。
- 普通调度与图捕获重放。
- 错误收集与资源诊断。

不支持的设备必须明确报错。
GPU模式不得自动切回CPU。
调用方自行选择应用物理后端。

### 资源生命周期

提交返回完成令牌。
令牌表示输出何时可以读取。
缓冲必须存活至提交完成。
销毁设备前必须处理在途任务。
跨线程访问遵守Rust所有权。

底层unsafe集中放在适配层。
每处unsafe说明安全前提。
裸设备指针不构成安全接口。
外部指针必须提供所有者句柄。

### 执行计划

执行计划保存稳定的内核顺序。
缓存键至少包含以下信息：

- 后端、设备与驱动兼容信息。
- 编译器与内核版本。
- 模型拓扑与缓冲布局。
- 世界数量与工作区容量。
- 积分器、求解器与能力开关。
- 精度、快速数学与调试配置。

热路径不分配接触工作区。
预热结束后才捕获执行图。
捕获期间不触发JIT编译。

固定布局的参数更新可复用图。
具体复用能力需P10验收。
布局、地址或容量变化使图失效。
失效后重新编译或捕获。
运行时不得重放过期指针。

### 容量与错误

所有变长缓冲公开容量。
每个世界记录实际计数。
溢出必须产生可定位诊断。
诊断区分容量与求解失败。
运行时不得静默截断物理结果。

扩容只能在同步边界执行。
扩容需要更新图与视图版本。
训练框架决定重试或终止。
引擎不替任务选择失败奖励。

## 物理模块契约

具体时序对齐冻结版上游。
模块图只描述数据依赖。

```text
模型与当前状态
  ├── 运动学、空间惯量与质量矩阵
  ├── 碰撞候选、接触与约束
  ├── 被动力、执行器与外力
  └── 传感器所需中间量
                  ↓
            约束与动力学求解
                  ↓
            积分与新状态写入
                  ↓
          查询结果与同步完成状态
```

分阶段接口保留上游语义。
接口区分更新状态与更新派生量。
传感器明确读取哪个物理阶段。
积分器不得改变上层控制周期。

### 精度与确定性

GPU兼容验收先采用f32。
原生双精度输入需显式转换。
比较报告记录双方dtype。
误差容限考虑精度与算法差异。
CPU参考测试不构成应用后端。

数值探针可以关闭快速数学。
各配置分别验收误差与性能。
渲染产品默认仍对齐上游。
渲染默认开启快速数学。
默认配置必须单独通过验收。
对比上游时匹配双方数学配置。
归约顺序可能影响结果。
接触切换可能放大轨迹差异。
项目不保证跨设备逐位相同。

## 目标公开接口

下表给出接口方向。
首版契约给出部分签名草案。
实现时再固定可调用签名。
它不是现有可调用API。

| 目标概念 | 语义 |
| --- | --- |
| `HostModelView` | 借用已编译模型的只读视图 |
| `ModelInput` | 通过检查的模型输入与资产 |
| `upload_model` | 转换模型并创建GPU资源 |
| `Model` | 指定设备上的模型资源 |
| `Data` | 多世界状态与工作区 |
| `Simulator` | 物理提交与配置入口 |
| `step` | 提交完整物理步 |
| `forward` | 更新正向派生量 |
| `inverse` | 计算逆向动力学 |
| `reset` | 重置指定世界 |
| `state_view` | 借用状态的设备视图 |
| `snapshot` | 导出明确版本的状态 |
| `render` | 提交批量相机渲染 |
| `Completion` | 表示在途操作完成状态 |
| `Diagnostics` | 返回错误、容量与数值状态 |

reset覆盖完整动态状态。
它包含历史、时钟与执行器状态。
扩展快照不替代状态打包入口。
等价set_state只写签名字段。
调用方决定何时刷新派生量。
快照不得保存裸设备地址。
快照不与策略权重混用。

完整step与分步分别验收。
上游RK4分步采用Euler。
调用方不得假定两者等价。
积分后派生量可能仍对应旧状态。
等价渲染与查询读取现有缓冲。
严格门面另行检查派生版本。
等价step2不要求step1票据。

## GPU张量互操作

状态视图必须描述以下字段：

| 字段 | 约束 |
| --- | --- |
| 设备与上下文 | 调用方必须验证一致性 |
| 地址与长度 | 保证边界及生命周期 |
| dtype | 不允许隐式误读精度 |
| shape与strides | 明确世界及对象维度 |
| 对齐与布局版本 | 防止过期布局复用 |
| 所有者句柄 | 保持资源存活 |
| 读写权限 | 防止训练与物理并发写入 |
| 完成令牌 | 建立跨流读写顺序 |

同一GPU不保证同一上下文。
学习库同生态也不保证零拷贝。
不同设备后端不能默认共享指针。

引擎先提供安全复制与视图。
再验证零拷贝与跨流事件。
若首版保留复制，须报告成本。
不得用零拷贝替代正确同步。
LRsLab负责具体学习库适配。
引擎不加入学习库张量依赖。

## 批量渲染契约

无窗口核心输出图像缓冲。
引擎不决定图像展示方式。
LRsLab负责展示与交互。
原生查看器不替代GPU批量渲染。
原生离屏接口也不证明批量吞吐。
GPU渲染可采用原生或Rust内核。

渲染输出明确以下信息：

- 世界与相机索引。
- 分辨率与像素布局。
- 颜色格式与色彩空间。
- 深度单位与无命中规则。
- 分割ID与对象映射。
- 行步长与设备所有权。
