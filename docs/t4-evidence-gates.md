## 精度来源检查

检查器固定24个物理入口。
它也固定30份变体的覆盖量。
删掉入口与变体仍不能通过。
缺件、重复件和额外入口均禁行。
源码漂移与非法路径也禁行。
回执必须匹配冻结字节哈希。
只修改通过标记不能绕过检查。
源码和PTX也各有独立哈希。

每份物理回执保留以下条件：

| 条件 | 冻结值 |
| --- | --- |
| 精度门禁 | `f32-physics`且通过 |
| 编译器 | NVRTC 12.8 |
| 融合乘加(FMA) | 开启 |
| 快速数学(fast-math) | 关闭 |
| 目标 | `compute_70` |
| 语言 | C++17 |
| 数学库例外 | 仅既有角度约简三元组 |

四个入口只操作整数标记。
清单明确标记其整数计算。
其余入口标记f32物理计算。
整数输出不代表内部没有f32。
例如肌腱唤醒会比较浮点限位。
私有i32标记不同于上游bool ABI。
清单不把两者描述为相同ABI。

映射列出上游函数与结果字段组。
复制和合并没有一一对应内核。
清单明确记录这些边界。
当前检查证明来源与文件完整性。
它不证明逐算子语义全部相同。
它也不补齐全部输入字段映射。

### 独立诊断的处理

三个测试入口不计入物理清单：

```text
adapter_probe
fma_probe
hessian_probe
```

其中一份f64回执记录拒绝结果。
它属于预期失败的ABI负例。
它不属于物理内核失败。
检查器只允许这三个排除名。
它不允许排除任意物理入口。

## 性能证据条件检查

本轮没有采集性能成绩。
正例时间全部来自合成真值表。
真值表只测试检查器行为。
它不进入真实性能报告。

检查器要求调用方冻结计划。
计划哈希绑定每条测量记录。
当前计划范围为完整G01。
它保留四组世界数：

```text
1, 2, 5, 513
```

每个样本执行四次状态更新。
双方均须覆盖全部批次。
记录不得缺项或重复。
检查器还要求以下条件：

| 类别 | 必须一致或齐全的证据 |
| --- | --- |
| 输入 | 有效模型、量化输入与状态哈希 |
| 版本 | 双方源码版本、产物哈希及计划哈希 |
| 设备 | 同一GPU标识与驱动 |
| 精度 | f32、FMA开启、快速数学关闭 |
| 范围 | 完整常驻G01，不含传输 |
| 预热 | 双方采用计划指定次数，且大于零 |
| 同步 | 每个样本前后均同步 |
| 计时 | 多个有限正数稳态样本 |
| 显存 | 全进程设备分配峰值及基线 |
| 追踪 | 完整分配事件，不用轮询快照替代 |
| 前置 | 数值正确性通过、独占GPU |

分配峰值不等于板卡占用。
它也不等于驱动实际驻留峰值。
双方必须采用同一明确口径。
事件记录须覆盖运行库分配。
检查器会拒绝不完整追踪声明。
采集器和事件真实性仍须审查。
仅填写这些字段不能证明实测。
现有板卡快照不能通过此门禁。
冷启动墙钟也不能通过此门禁。

实现见[证据检查器](../tests/support/t4_evidence.rs)。
它目前由独立宿主测试使用。
未来性能采集器须调用它。
本轮尚未实现性能采集器。
