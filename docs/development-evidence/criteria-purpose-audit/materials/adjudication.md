## 2. B 组（参考-前提型）：全部降级，不得单独作发布依据

### 2.1 四条硬规则（写死）

- **B-1 发布依据必须有 A 类判据。** SDF 发布用 CR-17；B 组任何一条（单独或组合）不得单独支撑发布声明。
- **B-2 每条使用点必须写明四项前提**：同 recipe / 同编译形态（FMA 结合方式）/ 同 GPU+驱动 / 同 warp 版本。任一前提不成立 ⇒ 该判据「**不适用**」（降级），既不得当作通过，也不得当作失败。
- **B-3 不做数值改动。** 本次及后续落地不改 `MAX_DEPTH_ULP=4`、RGB ≤1 LSB、`4 ULP@scale`、`2e-6` 等任何数值；要改必须新判据版本 + 用户重签。
- **B-4 已验收结论的处理。** 在「同配方」（同 recipe / 同编译形态 / 同 GPU+驱动 / 同 warp 版本）前提下结论仍有效，只需在文档与证据 README 注明前提；跨场景/跨形态引用一律按「不适用」处理，不回滚已验收结论、不改判据数值。

### 2.3 B 组前提句子模板（每条复制到使用点/文档）

通用骨架：

> 本判据为参考-前提型：**仅在同 recipe、同编译形态（FMA 结合次序一致）、同 GPU+驱动、同 warp 版本下有效**；上述前提任一不成立时本判据不适用，不构成数值正确性结论，也不得单独作为发布依据。

逐条填法（可直接引用）：

- **CR-10**：`MAX_DEPTH_ULP=4` 仅适用于「同 recipe（mujoco_warp/warp 版本一致）、同编译形态（上游生成 kernel 对 `a=dot(vec,vec)` 的 FMA 结合次序与参考采集时一致）、同 GPU+驱动、同 warp 版本」下、且参考与产品为同一 kernel 形态（同一渲染路径、同场景族）的 depth 比较；跨场景或跨 kernel 形态时**不适用**。
- **CR-11**：depth 位级（`mismatched==0`）仅在「同求值顺序、同编译形态、同参考采集环境」下成立；形态不同的两条实现之间不要求位级相等。
- **CR-12**：RGB ≤1 LSB 的界来自 8-bit 量化（每通道 1 个量化步长），前提是「同量化/舍入口径、同相机与分辨率、同 tonemap 配置」。
- **CR-16**：DepthSeg 跨路径位级相等的前提是「同 f32 求值顺序、同编译形态、同 GPU+驱动」；`megakernel` 与 `render_depth_seg` 任一处求值顺序不同即降级。
- **CR-18**：本条为**事故记录**（U4 attempt1/2/3 + 回滚），不构成判据、不再新增用途。
- **CR-23**：上游常量镜像的前提是「同上游版本（mjwarp/mujoco_warp 对应常量来源版本）、同编译器 FMA 收缩形态、同碰撞算法路径」；跨编译器/跨平台需重核。
- **CR-24**：`bit_equal` 优先 + `4 ULP@scale` 的前提是「同上游 recipe、同 GPU+驱动、同场景与 scale 口径」；4 ULP 无误差模型，不得跨 case/场景复用。
- **CR-25**：witness 判据只在已声明的采样面内有效，采样面外不可推断等价；1/24 超界维持「记录未决」。
- **CR-26**：4 ULP / 4.8e-7 的参考在 **CPU 侧**（CPU 上游参考），产品侧是 GPU/编译器收缩形态；仅作诊断/回归趋势，不可作 GPU 位级发布依据。
- **CR-27**：`TOLERANCE=2e-6` 的前提是「同 recipe、同冻结设备输出脚本」；数值来源需写明（非「一直这么用」）。
- **CR-28**：宿主探针 1e-6 只证明 CPU 侧近似一致，不替代设备执行。
