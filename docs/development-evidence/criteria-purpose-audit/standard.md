# 机器判据裁定标准 v1（审计标准）

## 1. 三问（每条判据必须能回答）
1. 裁定目标：这个判据要决定什么？（发布 / 能力解锁 / 内部回归 / 完整性）
2. 服务对象：谁消费这个结论？（用户发布 / 上游等价 / 门禁）
3. 被测物本质：被测物到底是什么？（SDF = gtype==8 按底层 mesh 求交；物理 = f32 运算链；证据 = 字节完整性）

## 2. 测量与界
- 界必须由「被测物属性 + 误差模型」推导并写明推导；或
- 参考型判据必须写明前提：同编译形态 / 同 recipe / 同 GPU / 同 warp 版本；前提不成立 ⇒ 该判据不适用（降级）。
- 禁止「参考数值直接当界」而不写前提；禁止「历史一直这么用」当理由。

## 3. 分类
A 本质-推导型：可作发布依据。
B 参考-前提型：仅在声明前提下有效；跨场景/跨形态即降级；不得单独作发布依据。
C 完整性-哈希型：只证明留痕/字节一致，不涉及数值正确性。

## 4. 高危筛查
- 位级判据但参考来自不同 kernel 形态/场景；
- 容差常量无推导注释/无来源；
- 同一判据被跨场景或跨平台复用而未复核前提；
- 用证据完整性代替数值正确性；
- 用「诊断已定位」代替通过。

## 5. 流程（不可跳）
QA 按本标准审计 → 报告 Chief（只报告 + 分类 + 影响面，不自行改判据/数值）→
Chief 定夺（A 保留 / B 补前提并降级 / C 不动）→ 落地；
仅「放宽数值 / 改参考 / 对外发布声明」三类签名级事项报用户。
