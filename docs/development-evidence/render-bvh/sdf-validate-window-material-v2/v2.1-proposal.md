Status: **PROPOSAL - not in force.** Nothing in this document is a criterion, nothing was
signed, and no criterion, reference, fixture, kernel or code value was changed to produce it.

Context: under the signed `render-sdf-criterion-v2` (B = 128 ULP) the attempt4 freeze step

1. the v2 section-2 predicate (4-neighbour outline band) covers only 9/183 (recipe) and

## A. Exact difference set as the list (replaces the three-condition predicate)

Definition (per arm): `list(arm) = { p : depth_bits_form_A(p) != depth_bits_form_B(p) }` over
all camera-1 sphere pixels, where form A is the `a` association (0,1,2) (scene-a reference
form) and form B is (1,0,2) (product form after the a-order refix).

Measured (exact replay, reproduces attempt3 bit-for-bit):

| arm | sphere pixels | list size | first differing pixel | first xy | max observed ULP |
| --- | --- | --- | --- | --- | --- |
| recipe (spp=1) | 747 | **183** | 28969 | (169,120) | **73** |
| render_kernel_flags aa2 (spp=2) | 745 | **172** | 29448 | (168,122) | **91** |

Both first-differing pixels are exactly the attempt3 first-difference records
(`render_kernel_depth_seg` / `render_skybox_reference` / `render_e2e` / `render_kernel_rgb`:
28969 = (169,120); `render_kernel_flags` aa2 arm: 29448 = (168,122)).

Why "outside the list delta = 0" holds constructively: the list is not a geometric heuristic,
it is the complete difference set of the two association forms over every sphere pixel of the
frozen reference. The product after the refix computes form B; the reference is form A.
Therefore the product can differ from the reference only on pixels where the two forms differ,
i.e. exactly on `list(arm)` - every pixel outside it must compare bitwise equal. The window
verifier enforces this directly and fail-closed:
- outside the list: any non-zero delta (1 ULP included) fails;
- inside the list: `|delta| > B` fails;
- list membership itself must match pixel-for-pixel (an extra or missing pixel fails), so the
  tool cannot shrink or grow the list at compare time.

Freeze contract (proposed):
- one list file per arm: `scene-a-sphere-outline-<arm>.txt` (ASCII, LF) with a header
  (criterion version, reference path + sha256, camera/raster/spp, columns) and one row per
  listed pixel, sorted by pixel index:
  `pixel x y ref_seg_geom ref_seg_type ref_depth_bits formA_bits formB_bits ulp_ab`
  (the per-pixel bound column of section B is added by the step-3 tool update);
- the list file sha256 goes into the guards file and the window evidence, and both lists are
  part of the frozen 92-entry guard set; rewriting a list inside the window is a failure;
- the freeze-time tool re-derives the lists from the pinned fixtures and must reproduce these
  hashes; a mismatch fails before the body starts.

## B. Per-pixel strict bound (same formula as v2 section 3, evaluated per pixel)

For every pixel in the list, evaluate the v2 section-3 formula with that pixel's own inputs
(its `|c|`, its `a`, its `sqrt(det)`, its `depth`, its `ULP(depth)`), then multiply by 1.15:

```
bound(px) = 1.15 * [ 5u * |c(px)| * |vz(px)| / (2 * a(px) * sqrt(det(px))) ] / ULP(depth(px))
```

Measured distribution over the list pixels (margin = bound * 1.15):

| arm | bound min | bound median | bound max (pixel) | observed max | max observed/bound | median ratio | pixels with ratio >= 1 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| recipe | 29.20 | 36.95 | **414.57** (29216) | 73 | **0.4005** (30409: 13/32.46) | 0.194 | **0** |
| aa2 | 29.16 | 37.26 | **494.52** (32587) | 91 | **0.4203** (29687: 19/45.20) | 0.195 | **0** |

Interpretation: the error model holds (no pixel exceeds its own bound; the worst observed delta
is 0.42 of its bound), but the analytic bound is **loose**: on every list pixel the bound is at
least ~2.4x the observed delta. The loose factor comes from the model constants (delta-a <=
4u*a, 5u*|c| and a ~= 1), not from the data.

Old "independent extremes multiplied" caliber, as a contrast:

| arm / set | sqrt(det)_min | |c|max | |vz|max | raw bound | x1.15 -> pow2 |
| --- | --- | --- | --- | --- | --- |
| recipe / band4 (90 px) | 2.199769e-03 | 1.894825 | 0.974813 | 1049.60 | 2048 |
| recipe / derived affected (183 px) | 6.356325e-03 | 1.894825 | 0.974192 | 363.01 | 512 |
| aa2 / band4 (89 px) | 5.233964e-03 | 1.894825 | 0.974513 | 441.00 | 512 |
| aa2 / derived affected (172 px) | 5.233964e-03 | 1.894825 | 0.973897 | 440.72 | 512 |

Honest note on that contrast: on the exact-difference set the independent-extremes value and
the per-pixel maximum almost coincide (363.01 vs 360.49 recipe; 440.72 vs 430.02 aa2), so the
"extremes come from different pixels and the product is unreachable" effect is NOT the main
gap here - it only becomes large (2048) when the old band4 predicate drags in pixels that are
not in the difference set and have a much smaller sqrt(det). The real gap between the
recomputed bound and the observed deltas is the ~2.4x looseness of the analytic model.

## C. Candidate B values (both listed; no value changed)

### C1. B_rigorous = 512 ULP
`B_rigorous = next power of two >= max(bound(px) * 1.15)` = 512 ULP (both arms; recipe max
414.57, aa2 max 494.52).
- Basis: strict per-pixel application of the signed v2 section-3 formula; every listed pixel
  is then covered by the derived bound, so the criterion stays "derive-guaranteed".
- Risk / cost: 512 is 5.6x the observed worst case (91 ULP). The criterion would formally
  admit deltas far beyond anything observed, and the numeric jump from the signed 128 is
  large, so it needs an explicit signature and a written rationale.
- Note: only 4 pixels per arm have a per-pixel bound above 128 (recipe max 414.57 at pixel
  29216, observed there 73; aa2 max 494.52 at pixel 32587, observed there 91), so the 512 is
  driven by a handful of near-tangent pixels.

### C2. B_empirical = 128 ULP (unchanged from the signed v2)
- Basis: observed maximum on the frozen lists is 73 ULP (recipe) and 91 ULP (aa2), i.e. a
  1.41x margin over 91; it also keeps the signed value and requires no numeric change.
- Risk / cost: 128 is NOT supported by the strict per-pixel bound - 4 pixels per arm have a
  strict bound above 128, so under the strict error model the criterion could admit a pixel
  that then exceeds B, and the "fail-closed by derivation" property is weakened to
  "fail-closed by observed calibration". If the reference or the frozen ray grid ever change,
  the 1.41x margin is not protected by the model.
- This is the value currently signed; listing it does not change it.

The two candidates differ only in the numeric limit; changing the list predicate (section A) is
the essential fix and is required by either candidate.

## D. What step 3 would change after the user signs (not done now)

1. New criterion version (e.g. `render-sdf-criterion-v2.1`): section 2 becomes the exact
   difference set of section A, section 3 becomes the per-pixel bound of section B with the
   signed B; spec, receipt and signing block updated.
2. Authoring tool contract: emit the list files in the section-A format only (affected pixels)
   plus a per-pixel bound column and the distribution statistics; same pinned-environment,
   fail-closed, offline, zero-GPU wrapper, same two-run determinism and sha verification.
3. Window material: guards carry the two list sha256 values; preparation checklist gains
   "list hashes match the freeze-time re-derivation"; the freeze step fails if a hash differs.
4. Then the normal window path (fresh freeze -> guards-only -> body -> post-window recheck ->
   evidence commit -> QA review). Separate check still required: the pre-window baseline is
   re-sampled at window time and must be >= the signed floor (5328 MiB); the current desktop
   graphics load (util 93%) must also clear the regular monitor threshold.
